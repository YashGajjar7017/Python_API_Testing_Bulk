# AI Prompt: RMS Device Direct AP Testing Suite Project Specification

You can use the following prompt to recreate or extend this project using any AI model:

---

## Prompt Instructions

Create a production-grade, highly responsive Python desktop GUI application using `tkinter` and `ttk` to test and configure an IoT Gateway device over its local direct Access Point (AP) connection. The default gateway IP address is `http://192.168.4.1`.

### 1. Connection & Login Setup
- **Fields:** AP Name Input (default: `RMS-2074`), Role Combobox (`Viewer`, `Operator`, `System Admin`, `Security Admin`), Password Entry (auto-fills from a default credentials dictionary: Viewer -> `viewer_001`, Operator -> `operator_001`, System Admin -> `sysadmin_001`, Security Admin -> `secadmin_001`), and Session Token Entry.
- **Login Action:** A button to POST to `http://192.168.4.1/api/login` with `{"username": <AP Name>, "password": <Password>}`. On success (200 OK), extract the session cookie (`session`) or JSON token (`sessionToken` / `session`) and store it. **Clear the automatic cookie jar list (`http_session.cookies.clear()`) and set the Cookie header manually (`Cookie: session=<token>`) alongside the Authorization header (`Authorization: Bearer <token>`) directly in the HTTP session headers dictionary to ensure a single, clean header format is sent, preventing microcontroller HTTP parser lockouts.**
- **Expiration Timer:** Implement a 60-second session token timer. If expired, update status to "Token Expired!" and alert the user. If the pipeline is running, do not cancel early, but wait for completion.

### 2. Layout & Dynamic Resizing
- **Geometry:** Start the window with `1500x900` geometry and maximize it automatically on Windows using `root.state('zoomed')`.
- **Responsive Layout:**
  - Connection pane on top (fill="x").
  - A main vertical `ttk.PanedWindow` to allow the user to adjust the Request Preview panel height up/down.
  - Top pane of the vertical PanedWindow contains the Request Preview frame (weight=1).
  - Bottom pane of the vertical PanedWindow contains a horizontal `ttk.PanedWindow` (weight=4) containing:
    - Left frame (weight=3): Scrollable `ttk.Treeview` containing columns: Select, Sr, Name, Method, URL, Read Acc, Write Acc, Read Status, Write Status. Columns must expand proportionally with the window (`stretch=True` for Name, URL, Statuses).
    - Right frame (weight=2): Scrollable Text Area ("Received Response Output") to display response details. Make this text area read-only.
  - Bottom status bar frame containing Status Label, Timer Label, and Export buttons.

### 3. API Execution Pipeline
- Maintain a list of endpoints matching this structure:
  - **Endpoint mapping:**
    - Sr 1: Write API Login (`POST http://192.168.4.1/api/login`, payload generated dynamically from current inputs)
    - Sr 2: Read API Login (`GET http://192.168.4.1/api/auth/status`)
    - Sr 3: UUID Configuration (`POST http://192.168.4.1/api/config/parameter`)
    - Sr 4: UUID Verification (`GET http://192.168.4.1/api/config/parameter?table=1`)
    - Sr 5: ISP Settings (`POST http://192.168.4.1/api/config/isp`)
    - Sr 6: ISP Readback (`GET http://192.168.4.1/api/config/isp`)
    - Sr 7: Remote Server Settings (`POST http://192.168.4.1/api/config/remote-server`)
    - Sr 8: Remote Server Readback (`GET http://192.168.4.1/api/config/remote-server`)
    - Sr 10: Broker Connect (`POST http://192.168.4.1/api/device/broker/connect`)
    - Sr 11: Broker Connection Status (`GET http://192.168.4.1/api/device/broker/status`)
    - Sr 12: Read Inverter Config (`GET http://192.168.4.1/api/config/inverter-communication`)
    - Sr 13: Write Inverter Config (`POST http://192.168.4.1/api/config/inverter-communication`)
    - Sr 15: History Data Download (`GET http://192.168.4.1/api/history?day=2026-05-29&vd=5&offset=&limit=96`)
    - Sr 16: WIFI Status (`GET http://192.168.4.1/api/device/config/update`)
    - Sr 17: WIFI Setup (`POST http://192.168.4.1/api/device/config/update`)
    - Sr 18: Certificate RootCA PEM (`POST http://192.168.4.1/write.html?filename=rootCA.pem`)
    - Sr 19: Certificate Private Key PEM (`POST http://192.168.4.1/write.html?filename=key.pem`)
    - Sr 20: Certificate Client PEM (`POST http://192.168.4.1/write.html?filename=client.pem`)
    - Sr 23: MQTTServer Settings (`GET http://192.168.4.1/api/config/mqtt-server`)
    - Sr 24: MQTTServer Post (`POST http://192.168.4.1/api/config/mqtt-server`)
    - Sr 25: Firmware Update (`POST http://192.168.4.1/update`)
    - Sr 26: Modbus Poll Access (`Get/POST http://192.168.4.1/api/modbus`)
    - Sr 27: Fiddler Request (`Get/POST http://192.168.4.1:85/list.html`)
    - Sr 21: Restart (`Get/POST http://192.168.4.1/restar`)
- **Pipeline Execution:** When "Run Selected APIs" is clicked, run tests sequentially in a daemon thread. Sleep for `0.3` seconds between endpoints.
- **Strict Role Enforcement:**
  - Before sending a Write (POST) or Read (GET) request, verify if the role has permissions.
  - If a role does not have Write permission, skip POST and show `"-----"`.
  - If a role does not have Read permission, skip GET and show `"-----"`.
  - This prevents unauthorized requests which invalidate the active session token.
- **Avoid Token Invalidation:** When testing Sr 1 (Write Login API) in the execution pipeline, dynamically fill the username and password from the GUI inputs. Update active session cookies and headers immediately with the newly returned token.

### 4. Role-based Authentication Mappings
The permissions mapping must strictly align with this matrix:
- **Viewer:** Read-Only endpoints (Sr 2, 4, 6, 8, 11, 12, 15, 16, 21, 23).
- **Operator:** Read access on core endpoints, Write access on Sr 1, 26.
- **System Admin:** Read access, Write access on Sr 1, 3, 13, 26.
- **Security Admin:** Full write access (Sr 1, 3, 5, 7, 10, 13, 17, 18, 19, 20, 24, 25, 26).

### 5. Status Reporting & Error Display
- Just execute the requests and return the raw HTTP response status codes directly (e.g. `"200 OK"`, `"404 Not Found"`, `"401 Auth Failure"`). Do not perform text pattern checking (mismatched/match) against payloads.
- Selection Click Event: When a row in the treeview is clicked, search the list of completed results. If a completed result exists, display its raw HTTP response outputs and headers in the right-side output area. Otherwise, show: `"No execution result yet. Run the APIs to see output."`

### 6. Export Report Outputs
- Provide four export formats in the status footer:
  - **Export PDF:** Outputs a letter-size grid table.
  - **Export Excel:** Saves workbook containing columns Sr, Name, Read Status, Write Status, Output.
  - **Export CSV:** Writes the testing outcomes to a `.csv` comma-separated file.
  - **Export JSON:** Serializes the complete execution result objects to a `.json` array file.
